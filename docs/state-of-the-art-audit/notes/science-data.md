# Scientific methodology and data engineering audit

Audit date: 2026-11-13. Author: scientific/data research reviewer. Production source, curation, data and deployment were not changed. Findings below distinguish executed probes, source inspection, literature claims and recommendations. References to files are repository-relative with line anchors; line anchors describe this inspected checkout. The audit is not certification of spacecraft safety.

## 1. Is the implemented scientific pipeline defensible and complete?

### Takeaway

The core deterministic scientific architecture is appropriate and the FLEX arithmetic reproduces original rows. The important frontier gap is measurement semantics and experimental identity, not lack of a more complex ML model. Confirmed inconsistencies remain across generic query, comparison, evidence labels and model export; these can mislead an agent even when individual arithmetic is correct.

#### Confirmed high-priority scientific defects

**SCI-01 — Non-extinction zeros remain in generic statistics (High; executed).** `compare()` masks zero Dext with non-Extinction outcomes, but `Tools.query(aggregate='summary')` and investigation variable summaries use the original scalar values. Probe selected all eight such FLEX rows and returned `n=8, median=0.0 mm, q1=q3=min=max=0.0`. The same rows are correctly excluded by comparison tests. This is an inconsistent semantic policy, not a rounding error. A raw-data table may retain zero exactly as NASA supplied it; a scientific “extinction diameter” distribution must apply the documented outcome policy. Add a shared `analysis_values(quantity, purpose)` layer preserving raw values, producing analysis value plus exclusion reason/outcome counts; use it in summaries, comparison and charts. Do not erase raw zeros. Test the same cohort through all public tools. [Query](../../../backend/src/embernova/tools.py:227); [investigation summary](../../../backend/src/embernova/tools.py:164); [comparison fix](../../../backend/src/embernova/science/analyses.py:36)

**SCI-02 — Derived measurements cited as measured (High; executed).** The long table correctly stores `o2_partial_pressure` as derived with formula, but `rows_evidence()` assigns value_kind from the dataset (“measured”) and omits per-value derivation/value_kind from previews. A partial-pressure query returned evidence `value_kind='measured'`. Citing that evidence as Measured can pass a kind check despite the transformation. Preserve field-level provenance in previews and citation validation; either separate derived evidence from measured evidence or support mixed evidence with per-field kinds. [Derived ingestion](../../../backend/src/embernova/ingest/tables.py:188); [evidence shaping](../../../backend/src/embernova/tools.py:38)

**SCI-03 — Export counts duplicate CFI experimental identities (High; executed).** The “one measured test” data-card claim conflicts with **158 exported CFI records for 79 unique Flex Numbers**: conditions and workbook records represent the same experiments but have distinct table-prefixed run IDs. This is not the eight exact duplicate CSV rows, which are correctly excluded. Coverage grid totals also count table records, including CFI workbook records as additional tests with unknown oxygen. Do not join opportunistically on an arbitrary fuzzy key. Curate a verified cross-table `experiment_uid` relation for CFI Flex Number, check key cardinality and conflicting shared pressure, retain source-row IDs per field, and expose both source-record count and unique-experiment count. Immediate safe fix: label exports and totals as source records and warn of linked tables; long-term provide a validated merged modeling view. [Export](../../../backend/src/embernova/export.py:39); [data card](../../../backend/src/embernova/export.py:93); [coverage](../../../backend/src/embernova/science/analyses.py:465); [CFI mapping](../../../curation/tables/PSI-39__cfi_datasummary.yaml)

**SCI-04 — Oxygen-only solids envelope fails (High; executed).** `envelope()` accepts oxygen-only constraints and computes a useful BASS matching set but unconditionally makes an O2–pressure chart. BASS-only, solid-thin-only and nonexistent-investigation probes all raise `ValueError: No complete scalar values for these axes and filters; inspect raw/design cells or choose different variables`. In the first two cases the source has useful oxygen observations and missing pressure; that should be an honest partial result with an O2 strip. Separate coverage calculation from optional chart construction. Return chart=null/empty state and known-condition strips; validate nonexistent IDs separately. Add tests for solids only, CFI inverse only, missing pressure, no matching cohort, and requested flow only. [Envelope](../../../backend/src/embernova/science/analyses.py:192); [mandatory chart](../../../backend/src/embernova/science/analyses.py:273)

**SCI-05 — Measurement-specific context is flattened to row context (High; source + export probe).** Saffire-II mapping includes explicitly named normal-gravity ground spread/burn columns in rows whose `gravity_regime=microgravity_cygnus`; the export includes these columns and says “All tests are microgravity.” The column names do retain the distinction, so this is not hidden numerical corruption, but row-level claims and future model consumers can conflate regimes. Saffire oxygen is noted as investigator-derived from CO2 yet inherits table `value_kind=measured`. Add field-level value_kind, gravity, method and source context, preserving a relation between flight and ground comparison measurements. Immediate data-card caveat and exposed per-column notes can prevent the most likely misuse. [Saffire mapping](../../../curation/tables/PSI-99__saffire2.yaml); [inherited kind](../../../backend/src/embernova/ingest/tables.py:162); [export limits](../../../backend/src/embernova/export.py:130)

### Inferences

- Do not promote the prior judging review's quick leave-one-out regression as proof of a deployable predictor. Repeated/near-identical conditions can leak across random folds, the data may be dependent, and condition coverage is sparse. The existing ADR's grouped validation is substantially more defensible, but its statement equating convex-hull membership with Mahalanobis distance is mathematically wrong: an ellipsoid threshold is not a convex hull. Future architecture docs should distinguish hull feasibility, density/support distance and missing categorical configurations. [Specification](../../architecture/SCIENTIFIC_ANALYSIS.md:110); [prior exploratory claim](../../judging-review/04_SCIENTIFIC_AUDIT.md)
- Scientific correctness earns a provisional **6.5/10**, where 5 means deterministic arithmetic with material semantic gaps, 7 means consistent field-level provenance and comparison semantics, 9 requires independent scientist-reviewed derivations/uncertainty/external validation, 10 is not warranted by this audit. It is stronger for FLEX arithmetic than for general multi-dataset inference. Data quality/engineering earns **6/10** under an analogous rubric; source preservation is strong, canonical experiment identity and measurement-level context are weak. These are judgments, not measured benchmark scores.

### Gaps

- No full rehash/rebuild of 274 original payloads was performed; installed bundle hashes were verified by Bundle construction and failure-path tests. No all-cell comparison of every curated CSV/workbook against NASA originals, no new PDF image inspection, no independent expert scientific signoff, no uncertainty estimates manufactured. Unparsed telemetry, particle size workbooks and raw media remain unvalidated for scientific extraction. No real predictive model comparison was run. No claim that local snapshot represents all NASA results.

## 2. Is the data architecture the strongest practical choice?

### Takeaway

Keep SQLite, Parquet, pandas, DuckDB and Pint for this small corpus. Improve immutable release packaging, field provenance, identity and extraction coverage before adding infrastructure. Current DuckDB use eagerly loads full Parquet tables into pandas, so it does not exploit query pushdown for larger future datasets.

### Inferences

Highest-value dataset work is to curate missing **outcomes and experimental context**, not simply inflate investigation counts: Saffire-III telemetry (already in local corpus but not parsed), SAME/SAME-R size distributions, BASS material outcomes from publications, fiber/flow/geometry metadata, and recent Saffire/SoFIE studies with explicit provenance. NASA's repository documents both raw and reduced PI data and ongoing expansion; additions require separate source-versioned ingestion and must not retroactively mutate original snapshot. [NASA PSI history](https://www.nasa.gov/physical-sciences-informatics-psi/history-of-physical-science-informatics/)

### Gaps

No scale benchmark beyond current corpus; eager loading performance under million-row telemetry is predicted, not measured. No package vulnerability scan owned here. No archival/versioning service comparison benchmark. Original metadata can contain inconsistent study fields (the current PSI-98 public page, for example, shows a smoke proposal title alongside Saffire objectives), so NASA metadata should be displayed with source/version and curator notes rather than treated as infallible. [NASA PSI-98](https://psi.nasa.gov/physci/repo/data/investigations/PSI-98)

#### Concrete methodology choices and alternatives

1. **Descriptive comparison.** Current pooled median/IQR is a legitimate descriptive baseline. Alternatives: (a) exact condition strata with raw points and per-quantity n; (b) nearest matched cohorts using explicit tolerances plus balance diagnostics; (c) regression adjustment/hierarchical models with sensitivity analysis. Recommend (a) first because few heterogeneous records and missing apparatus details make causal adjustment fragile. (b) is EXPERIMENT; (c) remains research. “More adjusted” is not automatically more valid.
2. **Uncertainty.** Alternatives: (a) source-reported measurement uncertainty and first-order propagation; (b) Monte Carlo with documented correlated input distributions; (c) bootstrap independent experiments for sampling uncertainty. Select based on estimand, not convenience; bootstrap does not substitute for instrument uncertainty. For partial pressure, record X and P uncertainty/covariance and propagate through XP; for d² ratio retain correlation between K and the diameter history. Unknown uncertainty remains unknown.
3. **Applicability.** Alternatives: (a) observed joint points plus missingness strips; (b) convex hull or nearest-neighbor support within fuel/hardware class; (c) validated physical dimensionless regime maps. Choose(a) now; (b) is not a safety envelope and can include unobserved interiors; (c) requires physics-specific validation. Do not project one geometry's coverage to another.
4. **Ranking nearest evidence.** Current band-normalized offset is a retrieval aid. Alternatives: (a) separate unit-bearing offsets and deterministic sort, (b) user-supplied tolerance-scaled distance, (c) Pareto nondominated records showing trade-offs. Prefer(a) with class filters before deadline, benchmark(b)/(c) on expert choice labels later. Learning-to-rank has no credible scientific labels here and is unjustified.
5. **Prediction.** Compare per-fuel median, oxygen-only linear/ridge, and per-fuel Gaussian process against grouped repeated validation and a genuinely external campaign. Test categorical apparatus/fiber and condition leakage. Report MAE/RMSE in physical units, interval coverage/width and abstention coverage. No generic fire-risk or lunar extrapolation. Do not call Mahalanobis threshold a convex hull. Delay deployment until model passes predeclared gates; a null result is publishable engineering evidence.
6. **Time series.** Parse Saffire sensor units, sampling/time origins and calibration first; compare full resolution vs extrema-preserving/min-max vs LTTB for display only. Statistics always use full samples and report sensor time alignment; never infer spread speed from screen animation. No current timeseries module was found in the inspected backend.

### Inferences

Recommended architecture retains a tool-using scientific assistant around deterministic scientific functions. Data ingestion produces immutable source and measurement records, a curated identity graph links only verified same experiments, selection returns explicit exclusions and contextual compatibility, deterministic analyses return typed statistics/charts with full lineage, and the LLM narrates these outputs under evidence constraints. This improves several observed defects through one shared measurement-semantics layer rather than many UI-only patches.

### Gaps

Literature discovery is selective, not an exhaustive systematic review of all2024–2026 publications. Primary metadata/abstracts were verified; several publisher full texts were inaccessible and raw paper datasets were not reanalyzed. No result from S5 is an EmberNova benchmark. Broader corpus PDF/telemetry/media inspection and expert labels remain necessary. All estimated engineering effort is judgment, not measured delivery time. The best-achievable claim is therefore conditional on current corpus and deadline, not a proven global optimum.
